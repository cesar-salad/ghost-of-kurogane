EditMode verifies effective damage/healing, clamping, invalid values (negative, zero, NaN, infinity), one death event, no resurrection, and duplicate state-transition suppression. EditMode initializes Health's private Awake by reflection because ordinary runtime lifecycle callbacks do not automatically execute there.

PlayMode creates an isolated floor/player/camera rig and sends synthetic KeyboardState events through the actual Input System. It verifies camera-relative movement, sprint distance greater than walk distance, grounded state, jump ascent/landing, camera follow displacement, successful E interaction, and wall occlusion. A fixed capture delta keeps frame-based assertions stable. The fixture temporarily allows input without Game-view focus and restores the original input/time settings in teardown. These tests do not replace a manual check of the generated scene's rendering or cursor behavior.

Initial test-harness failures were corrected: Unity rejects SendMessage(Awake) on an EditMode runtime component; the headless Editor also filtered simulated input until test-only focus routing was set explicitly. Final results above are from successful reruns.

## Manual acceptance checks still required

1. Open Prototype_Playground, press Play, and focus Game view. Confirm player, floor, obstacles, lighting, and terminal render with no pink/error materials.
2. Walk forward/back/sideways, orbit the mouse, then walk again. Confirm facing and camera-relative direction feel right and collisions block obstacles.
3. Hold Shift while moving and jump while walking/running. Check slopes, edges, and landing visually; tune Inspector values as needed.
4. Face the terminal within 2.5 meters, confirm the prompt, press E, and inspect the Console. Walk out of range or place a wall between actor and terminal; the prompt must disappear.
5. Escape, focus loss, click-to-capture, and exiting Play mode should produce sensible cursor behavior on the target desktop.
6. Use the Test Runner for Health event verification; there is intentionally no damage/combat input or death presentation in this prototype.
7. Add the chosen scene to a Windows Build Profile and perform a standalone build/smoke test. No player build was made during this milestone.

The fallback camera has no collision avoidance, and only move has a gamepad binding. Cinemachine migration and full controller support remain future work. No claim of visual approval, complete gamepad support, or standalone build validation is made.
