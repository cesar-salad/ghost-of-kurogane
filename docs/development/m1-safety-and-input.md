# M1 - Fall recovery and gameplay input locking

Started 2026-11-06 after manual acceptance of the first M1 quality pass. M0 is Done based on developer-reported smoke acceptance and a second developer cloning/testing the build. This increment does not complete all of M1.

## Gameplay gate

PlayerInputReader.SetGameplayInputEnabled(false/true) gates movement, mouse look, jump, sprint, and interaction. Cursor release/capture still work. PlayerInteractor hides its current prompt while gated. Gravity and camera tracking continue; this is not a timescale pause or a frozen physics body.

Default bindings and action lifetime are preserved. Unlocking skips the current frame's gameplay reads so button edges from an ending interaction do not replay. Held movement/sprint resume on following frames; jump/interact require a fresh press. GameplayInputEnabled reflects the requested gate; CanReadGameplayInput additionally accounts for the component lifecycle and resume frame.

The API has one owner (eventually dialogue/cinematic control). It is not a nesting/lock-token framework. Callers must restore their own gate when ending or aborting an interaction. A complete player state model and pause UI remain future M1 work.

## Fall recovery

PlayerFallRecovery runs after movement. If the actor falls below Minimum World Y (default -10), it returns to the initial runtime pose, or a configured Return Point. The return point must be above the threshold and on safe ground; invalid heights log an error and disable recovery rather than looping.

PlayerController.Teleport temporarily disables collision sweeping, restores the previous CharacterController enabled state, and clears vertical/rotation smoothing velocity. Recovery then snaps the configured follow camera to the new target. It preserves input-lock ownership player and use the PlayerInputReader component's context menu > Lock Gameplay Input.
